# Engine — учебный движок на DirectX 12

C++17, DirectX 12 (фреймворк Ф. Луны в `Common/`), ECS, загрузка моделей (Assimp) и текстур (stb_image), job system (**enkiTS**), профилирование (**Tracy**).
Все библиотеки ставит **vcpkg**: вручную ничего качать и никаких путей в свойствах проекта прописывать не нужно.

## Как открыть и запустить

Нужна **Visual Studio 2022 или 2026** с нагрузкой «Разработка классических приложений на C++». В неё уже входят CMake и vcpkg.

1. **Файл → Открыть → Папка…** → выбрать эту папку (где лежит `CMakeLists.txt`). Файла `.sln` больше нет.
2. Вверху выбрать конфигурацию **x64 Debug** или **x64 Release**.
3. **Первый раз** конфигурация займёт 5–10 минут: vcpkg скачает и соберёт Assimp, glm, stb, nlohmann-json, enkiTS и Tracy. Дальше они берутся из кэша.
4. Цель **Engine.exe** → **F5**.

Командная строка (Developer PowerShell for VS):
```powershell
cmake --preset x64-release
cmake --build --preset x64-release
.\out\build\x64-release\Engine.exe
```
Ошибка «vcpkg.cmake не найден» означает, что не установлен компонент VS «Диспетчер пакетов vcpkg». Добавьте его через Visual Studio Installer или поставьте vcpkg вручную и задайте переменную `VCPKG_ROOT`.

## Кнопки

| Где | Кнопка | Что делает |
|---|---|---|
| везде | **W** | показать или спрятать второе окно (крутящийся квадрат) |
| везде | **F5 / F6** | сохранить / загрузить сцену (`scene.json`) |
| везде | **Esc** | выход |
| меню | **Enter** | начать игру (в меню сцена скрыта, виден только фон) |
| игра | **↑ ↓ ← →** | двигать камеру вперёд, назад, влево, вправо |
| игра | **Q / E** | камера вниз / вверх |
| игра | **ПКМ + мышь** | вращать камеру |
| игра | **ЛКМ + мышь вверх/вниз**, **колесо** | приблизить / отдалить |
| игра | **B** | стресс-сцена: 20 000 анимированных кубов (вкл/выкл) |
| игра | **J** | job system: параллельно / на одном потоке |
| игра | **P** | пауза |
| пауза | **P / Backspace** | продолжить / выйти в меню |

В заголовке окна: состояние, режим job system, число видимых и всех объектов, FPS.
**Для демо:** Enter → B → несколько раз J, глядя на FPS.

## Настройки: `config.json` (копируется рядом с exe)
```json
{
  "background_color": [0.39, 0.58, 0.93, 1.0],
  "vsync": false,
  "jobs":  { "enabled": true, "worker_threads": 0 },
  "scene": { "stress_entities": 20000, "stress_on_start": false, "seed": 1337 },
  "benchmark": { "warmup_frames": 300, "measure_frames": 2000, "output": "bench_results.csv" }
}
```
Аргументы командной строки перекрывают файл: `--bench`, `--jobs=on|off`, `--workers=N`, `--entities=N`, `--warmup=N`, `--frames=N`, `--out=файл.csv`, `--label=текст`, `--vsync=on|off`.

## Замеры до/после (п. 2.4 ЛР1)
Только Release. Скрипт кладётся рядом с exe:
```powershell
cd out\build\x64-release
powershell -ExecutionPolicy Bypass -File .\bench.ps1        # 3 прогона без job system + 3 с ней
```
Результаты: `bench_results.csv` (сырые данные) и `bench_summary.csv` (медианы по прогонам и ускорение).

## Tracy
1. Скачайте профайлер **той же версии, что в vcpkg (0.14.1)**: `windows-0.14.1.zip` на <https://github.com/wolfpld/tracy/releases/tag/v0.14.1>.
2. Запустите `Engine.exe`, в Tracy нажмите **Connect**.
3. На трейсе видно: потоки `Main thread` / `Job Worker N`, зоны `StressAnimation`, `RenderSystem::Prepare`, `RenderSystem::Record`, `ParallelFor range`, ожидания, графики `Frame time (ms)`, `Visible objects`, `Jobs in flight`.
4. Трейсы «до» (J выключен) и «после» (J включён): File → Save trace.

## Если что-то упало
Движок пишет в `engine.log` (рядом с exe) время, поток и уровень каждого сообщения. При падении туда же записывается стек вызовов. В Debug-сборке в лог попадают и ошибки D3D12 debug layer.

## Результаты замеров (п. 2.4)

**Условия.** Release x64, фиксированная сцена из 20 000 анимированных кубов (seed 1337),
VSync выключен, прогрев 300 кадров, замер 2000 кадров, по 3 прогона на режим
(`jobs=off` и `jobs=on`, 16 потоков). Железо: Intel Core i7-12650H (10 ядер / 16 потоков), NVIDIA GeForce RTX 4070 Laptop GPU, 16 ГБ ОЗУ.
В таблице медианы по трём прогонам (p95 и p99 тоже усреднены медианой).
Замер выполнялся без подключённого Tracy:

    powershell -ExecutionPolicy Bypass -File .\bench.ps1 -Entities 20000

| Метрика | off, медиана, мс | on, медиана, мс | Ускорение | off p95 | on p95 | off p99 | on p99 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Frame | 3,014 | 1,795 | ×1,68 | 3,534 | 2,194 | 3,958 | 2,360 |
| StressAnimation | 0,529 | 0,168 | ×3,15 | 0,892 | 0,192 | 0,953 | 0,221 |
| RenderPrepare | 0,916 | 0,220 | ×4,16 | 1,149 | 0,281 | 1,461 | 0,346 |
| RenderRecord | 0,145 | 0,158 | ×0,92 | 0,173 | 0,338 | 0,286 | 0,507 |

Медиана кадра соответствует примерно 332 FPS без job system и 557 FPS с ней.
Исходные данные: `results/bench_results.csv`, `results/bench_summary.csv`.

### Анализ цифр
- Кадр ускорился с 3,01 до 1,80 мс (×1,68). Хвост распределения тоже стал короче:
  p95 снизился с 3,53 до 2,19 мс (×1,61), p99 с 3,96 до 2,36 мс (×1,68).
- `StressAnimation` (×3,15) и `RenderPrepare` (×4,16) выполняются на воркерах.
  До переноса они занимали около 1,45 мс из 3,01 мс кадра, после около 0,39 мс.
  Хвосты этих зон сократились ещё сильнее (p99 `StressAnimation`: 0,95 → 0,22 мс).
- Кадр ускорился меньше, чем эти зоны, потому что остальная часть кадра
  (около 1,4–1,6 мс) не распараллеливается (закон Амдала). По трейсам это в первую очередь
  `Render::WaitForGPU` и последовательная запись команд `Record`.
- `RenderRecord` в медиане почти не изменился (0,145 → 0,158 мс), но его хвосты выросли
  (p95 0,17 → 0,34 мс, p99 0,29 → 0,51 мс). По трейсам эта зона выполняется на главном потоке
  в обоих режимах и в задачи не диспетчеризуется, поэтому причина роста хвостов не установлена.
  Возможное объяснение: данные, подготовленные другими ядрами, читаются из чужих кэшей.

### Трейсы Tracy
Файлы: `results/trace_off.tracy` (job system выключена), `results/trace_on.tracy` (включена).
Сняты на той же стресс-сцене (клавиша B, 20 000 сущностей), но при подключённом Tracy,
поэтому абсолютные времена выше, чем в таблице (накладные расходы профайлера).

| Параметр | off | on |
|---|---|---|
| Потоки на таймлайне | `Main thread` | `Main thread` + `Job Worker 1…15` |
| Frame time, диапазон, мс | 3,68 – 6,94 | 2,08 – 4,44 |
| CPU usage, диапазон | 1,8% – 14,6% | 0,9% – 31,9% |
| Visible objects | 4 708 – 4 718 | 4 707 – 4 718 |

Скриншоты: `results/trace_off.jpg`, `results/trace_on1.jpg`, `results/trace_on2.jpg`.

**Режим off, приближение на 4 кадра** (`results/trace_off_zoom.jpg`, кадры 3,95 / 3,88 / 4,15 / 4,15 мс):
- Все зоны выполняются на `Main thread`. `ParallelFor` работает в последовательном режиме
  (`ParallelFor (serial)`), то есть сравниваются два режима одного и того же кода.
- Порядок в кадре: `StressAnimation` → `RenderSystem::Prepare` → `Record` → `Render::WaitForGPU`.
- `StressAnimation` (~0,5–0,7 мс) и `Prepare` (~1,2–1,5 мс) заметно длиннее, чем в режиме on.

**Режим on, приближение на 3 кадра** (`results/trace_on_zoom.jpg`, кадры 2,29 / 2,48 / 2,83 мс):
- Порядок зон тот же. `StressAnimation` (~0,2 мс) и `Prepare` (~0,3 мс) запускают `ParallelFor`:
  диапазоны выполняют воркеры, главный поток участвует и ждёт завершения (`Wait for task`).
- Воркеры включаются короткими всплесками и остальное время простаивают (`Idle (no tasks)`);
  в одной фазе занята лишь часть пула (около 5–8 из 15).
- `Render::WaitForGPU` занимает больше половины кадра и по длительности (~1,3 мс)
  близка к режиму off.
- `Record` (`Render::DrawItems`) выполняется на главном потоке.

Значения со знаком `~` оценены по шкале времени на трейсе. Времена с Tracy выше,
чем в `bench.ps1`, поэтому для сравнения режимов используется таблица выше, а трейсы
показывают структуру кадра.

### Вывод
На 20 000 сущностей job system на enkiTS ускорила кадр в 1,68 раза (3,01 → 1,80 мс)
и сократила p99 с 3,96 до 2,36 мс. Распараллеленные зоны ускорились в 3,2–4,2 раза.
Дальнейший выигрыш ограничен ожиданием GPU и последовательной записью команд.
Побочное наблюдение: хвосты `RenderRecord` выросли.
